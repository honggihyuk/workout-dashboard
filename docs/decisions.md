# 결정 사항 모음

1~6차 인터뷰와 검수에서 확정한 결정을 한 곳에 모은 목록입니다. 결정이 바뀌면 이 문서와 해당 단계 문서를 함께 고칩니다.

- 표시: **확정** = 대표님이 직접 정함 / **기본값** = 대표님이 따로 정하지 않아 Claude가 정한 값 (언제든 변경 가능)
- 실사용자: 대표님 1명

## 1차 문제 정의 → [01-problem-definition.md](./01-problem-definition.md)

| 항목 | 결정 | 구분 |
|---|---|---|
| 목표 | 린매스업 (근육량 유지·증가, 체지방 감량, 체중 유지) | 확정 |
| 핵심 병목 | 기록이 쌓이지 않음 (까먹음, 식단 입력 번거로움, 관리 분산) | 확정 |
| 핵심 대상 | 운동(세트·무게·횟수, 러닝), 식단(한 끼 사진 + 선택 입력) | 확정 |
| 보조 대상 | 컨디션 간단 체크, 체중, 인바디 | 확정 |
| 제외 | 수면 (첫 버전) | 확정 |
| 운동 기록 방식 | 대시보드에서 직접 입력, 운동 끝나고 한 번에. Planfit 연동 안 함 | 확정 |
| AI 식단 추정 | 사용 | 확정 |
| KPI | 기록률(매일·주간), 인바디 골격근량 유지·증가, 체지방률 감소(월간) | 확정 |
| 벤치프레스 최고 무게 KPI | 제외 (1RM을 매번 재지 않으므로) | 확정 |
| 기록률 목표 | 운동 주 4회, 식사 사진 하루 2끼 이상 | 기본값 |

## 3차 UX/IA 설계 → [03-ux-ia-design.md](./03-ux-ia-design.md)

| 항목 | 결정 | 구분 |
|---|---|---|
| 기기 | 아이폰 기준. PC는 같은 화면이 넓게 열리는 정도 | 확정 |
| 메뉴 | 탭 5개: 오늘, 운동, 식단, 몸 변화, 설정 | 확정 |

| 달력 | 있음. 오늘 탭 위쪽 날짜를 누르면 열림 | 확정(있음) / 기본값(위치) |
| 오늘 화면 맨 위 | 이번 주 KPI | 확정 |
| 운동 전 비교 | 최근 몇 회 흐름 (5회) | 확정(흐름) / 기본값(5회) |
| 몸 변화 기본 기간 | 1개월 | 확정 |
| 보충제 칸 | 항상 보이고, 운동을 기록한 날만 루틴에 반영 | 확정 |

| AI 분석 실패 | 사진 저장 + 직접 입력 칸 열기 | 확정 |
| 축하 표시 | 조용한 표시 (애니메이션 없음) | 확정 |
| 영양제·보충제 9종 | 처음부터 등록 | 기본값 |
| 처음 입력한 운동 | 운동 목록에 자동 추가 | 기본값 |

## 6차 구축 및 검수 → [06-build.md](./06-build.md)

| 항목 | 결정 | 구분 |
|---|---|---|
| 순서 | MVP 범위 구축 → 검수 및 안정화 → 배포(CI/CD) → 추가 구축 | 확정 |
| MVP 범위 | 로그인, 오늘, 달력, 운동 전체 흐름, 식단(사진 + 직접 입력), 몸 변화, 설정. AI 분석·알림·엑셀은 추가 구축, 백업은 배포 단계 (AI 분석은 2026-10-16에 앞당김) | 확정 (기록 먼저) |
| 검수 방법 | 예시 기록이 든 체험판을 휴대폰에서 눌러 보며 검수 | 기본값 |
| 실제 서버 연결 시점 | 검수 및 안정화 단계 | 기본값 |
| 하루 상태·KPI 계산 | MVP는 화면에서 계산, 알림을 붙일 때 서버 계산 추가 | 기본값 |
| 러닝 루틴 | 루틴 종류에 러닝 추가 (목표 거리·평균 페이스). 러닝 기록은 거리와 평균 페이스로 적고 시간은 자동 계산 (나이키 런처럼) | 확정 (MVP v1 검수) |
| 러닝 루틴과 다음 차례 | 러닝 루틴은 헬스 루틴의 다음 차례 순서에 끼지 않음 | 기본값 |
| 러닝 위치 추적 | 넣지 않음. 홈 화면 웹앱은 화면이 꺼지면 위치 기록이 멈춰서, 달린 뒤 거리·페이스를 옮겨 적는 방식 | 기본값 |
| 러닝 페이스 범위 | 1km당 2분~30분 밖이면 저장 막음, 지난번보다 30% 넘게 다르면 "맞나요?" | 기본값 |
| 단백질 목표 | 하루 체중 × 1.5~2g. 먹은 단백질과 차이를 식단·오늘 화면에 보여 줌 | 확정 (MVP v1 검수) |
| 칼로리 비교 | 운동·러닝으로 쓴 칼로리를 계산해 먹은 칼로리와 비교 | 확정 (MVP v1 검수) |
| 칼로리 비교 방식 | 하루 쓴 칼로리 = 기초대사량(인바디, 없으면 체중 × 24) × 1.2 + 운동 활동 칼로리 | 기본값 |
| 운동 칼로리 계산 | 러닝: 체중 × 거리. 헬스: 세트 수 × 3분을 운동 시간으로 보고, 운동 강도 느낌으로 MET(3.5·5·6)를 골라 계산 | 기본값 |
| 쉐이크를 식단에 포함 | 쉐이크 1회 40g. 먹은 날 단백질·칼로리 합계에 더함 | 확정 (MVP v1 검수) |
| 쉐이크 성분 | 단백질 36g·150kcal (WPI 일반값). 설정에서 제품 영양표대로 고칠 수 있음 | 기본값 |
| 단백질 표 | 고기 등 음식별 100g당 단백질을 보는 표와, 무게로 계산해 식사에 더하는 기능 | 확정 (MVP v1 검수) |
| 단백질 표 내용 | 18가지 음식의 100g당 어림값(USDA·국내 연구 자료 바탕), 기본은 익힌 무게, 생 무게로 바꿀 수 있음 | 기본값 |
| MVP 검수 마무리 | MVP v1 검수를 마치고 다음 단계로 | 확정 (2026-10-16) |
| 사진 AI 분석(Gemini) 시점 | 추가 구축에서 앞당겨 검수 및 안정화 단계에 실제 서버 연결과 함께 | 확정 (2026-10-16) |
| 사진 분석 모델 | `gemini-3.8-flash` (2026-10 무료 등급에서 새 프로젝트 권장. 2.5 계열은 예전에 쓰던 계정만 쓸 수 있음). 설정값 `GEMINI_MODEL`로 교체 | 기본값 |
| 사진 분석 흐름 | 사진을 올리면 바로 분석 → "확인 필요"로 메뉴·칼로리·단백질 표시 → "맞아요" 또는 "고치기" | 기본값 |
| 확인 전 AI 추정 | 먹은 양 합계에 넣고, 확인 안 한 끼니 수를 따로 알려 줌 | 기본값 |
| 분석 실패 시 | "분석 실패" 표시 + 직접 입력 칸을 엶 + "다시 분석" 버튼. 하루 한도 초과·음식 아님·설정 문제는 이유를 다르게 안내 | 기본값 |
| 직접 적은 끼니의 사진 교체 | 직접 적은 값이 있으면 사진만 바꾸고 AI로 덮지 않음 | 기본값 |
| 분석 결과 저장 | 서버 기능은 추정만 돌려주고 저장은 화면이 함 (사진 직후 식사 기록이 아직 서버에 없을 수 있어서) | 기본값 |
| 서버 기능 올리는 방법 | Supabase 대시보드 편집기에 붙여 넣기 (자동 올리기는 배포(CI/CD) 단계에서) | 기본값 |
| 서버 기능 계정 확인 | 기능 안에서 로그인 토큰으로 허용 계정을 확인하고, 대시보드의 Verify JWT는 끔 (새 키 형식에서도 동작하게) | 기본값 |
| 연결 안내 | 대표님이 따라 하는 단계별 안내서 [setup.md](./setup.md) | 기본값 |
